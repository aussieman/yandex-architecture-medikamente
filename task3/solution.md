# Оценка Data Encryption at Rest and In Transit

### Введение
В рамках проекта "Медикаменте" разработана стратегия защиты данных, основанная на принципах Privacy by Design и требованиях российского законодательства (ФЗ-152, ФЗ-323). Стратегия учитывает шифрование данных в состоянии покоя (at rest) и во время передачи (in transit). Ключевые цели: обеспечение конфиденциальности, целостности и доступности данных, минимизация рисков утечек и соответствие профилю риска.

Стратегия включает классификацию данных, обоснование защиты, инструменты шифрования, автоматизированный контроль и реестр средств. Данные классифицированы по чувствительности (высокая, средняя, низкая), состоянию (at rest/in transit) и профилю риска (на основе потенциального ущерба от утечки).

### Классификация данных
Данные классифицированы на основе анализа бизнес-процессов (из диаграмм As-Is и To-Be). Профиль риска оценивается по шкале: высокий (риск репутационных потерь, штрафов >1 млн руб.), средний (риск финансовых потерь 100-500 тыс. руб.), низкий (минимальный риск).

| Данные | Состояние | Чувствительность | Профиль риска | Обоснование необходимости защиты |
|--------|-----------|------------------|---------------|---------------------------------|
| PHI (медицинские карты, заключения врачей, результаты анализов) | At rest/In transit | Высокая | Высокий | Содержат конфиденциальную медицинскую информацию. Утечка нарушает ФЗ-323, приводит к потере доверия пациентов и штрафам до 75 млн руб. (ФЗ-152). |
| PII (ФИО, дата рождения, телефон, email, адрес) | At rest/In transit | Высокая | Высокий | Персональные данные. Утечка нарушает ФЗ-152, риск идентификации и мошенничества. |
| Финансовые данные (чеки, платежи, суммы) | At rest/In transit | Средняя | Средний | Связаны с финансами. Утечка может привести к мошенничеству, штрафам по ФЗ-115. |
| Журналы и реестры (записи приёмов, учёт ТМЦ) | At rest | Средняя | Средний | Содержат агрегированные данные пациентов. Риск косвенной идентификации. |
| Системные логи (аудит доступа) | At rest | Низкая | Низкий | Не содержат чувствительных данных, но важны для compliance. |

### Обоснование необходимости защиты
- **Высокий профиль риска**: Данные PHI и PII требуют максимальной защиты, так как утечка может привести к дискриминации, шантажу или потере лицензии. В РФ такие данные подлежат обязательному шифрованию (приказ ФСТЭК №17).
- **Средний профиль риска**: Финансовые и реестровые данные защищаются для предотвращения мошенничества и обеспечения compliance с ФЗ-115.
- **Низкий профиль риска**: Логи защищаются для аудита, но с меньшими требованиями.
- **At rest**: Данные на серверах и дисках уязвимы к физическому доступу или хакерским атакам (например, через RDP).
- **In transit**: Передача без шифрования (как в As-Is) позволяет перехват (MITM-атаки).

### Инструменты защиты данных
Предлагаемые инструменты интегрируются в архитектуру To-Be (связи с зашифрованным хранилищем, DLP и аудитом).

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|---------------------------|---------------------|
| PHI/PII (at rest) | Предотвращение несанкционированного чтения при краже диска или взломе | Шифрование файловой системы (BitLocker/LUKS), PostgreSQL с pgcrypto, зашифрованное хранилище (Vault) с AES-256. |
| PHI/PII (in transit) | Защита от перехвата при передаче между системами (например, от ККМ к 1С) | TLS 1.3 для API, HTTPS для веб-интерфейсов, VPN для внутренних сетей. |
| Финансовые данные (at rest) | Защита от манипуляций и утечек | Шифрование БД (1С с встроенным шифрованием), резервное копирование с шифрованием. |
| Финансовые данные (in transit) | Безопасная передача платежей | TLS для интеграции с ККМ, шифрованные каналы в 1С. |
| Журналы/реестры (at rest) | Предотвращение изменений и утечек | Шифрование папок с тегами #PHI, контроль версий. |
| Системные логи (at rest) | Обеспечение целостности для аудита | Шифрование логов с HMAC для проверки подлинности. |

### Автоматизированный контроль
Для контроля используются:
- **DLP-система**: Автоматическое сканирование на теги #PHI/#PII, блокировка экспорта без подтверждения. Интеграция с SIEM для алертов.
- **Система аудита**: Логи всех операций (чтение/запись), анализ на аномалии (например, необычный доступ врача к чужим данным).
- **Мониторинг**: Victoria Metrics для метрик шифрования, алерты при попытках доступа без ключа.
- **Автоматические проверки**: Скрипты для валидации шифрования (например, тест на дешифровку без ключа).

### Реестр программных и аппаратных средств
| Средство | Тип | Назначение | Платформа | Стоимость (пример) |
|----------|-----|------------|-----------|---------------------|
| BitLocker | ПО | Шифрование дисков (at rest) | Windows Server | Включено в лицензию |
| LUKS | ПО | Шифрование дисков (at rest) | Linux | Бесплатно |
| PostgreSQL pgcrypto | ПО | Шифрование БД | Linux/Windows | Бесплатно |
| OpenSSL | ПО | TLS 1.3 (in transit) | Кросс-платформенное | Бесплатно |
| HashiCorp Vault | ПО | Зашифрованное хранилище | Linux/Windows | Открытый исходный код |
| McAfee DLP | ПО | DLP-система | Windows/Linux | ~500 тыс. руб./год |
| ELK Stack (Elastic) | ПО | SIEM для аудита | Linux | Бесплатно (open-source) |
| HSM (Hardware Security Module) | Аппаратное | Генерация/хранение ключей | Серверное | ~1 млн руб. |
| VPN-сервер (OpenVPN) | ПО/Аппаратное | Шифрованные каналы | Linux | Бесплатно |

Эта стратегия обеспечивает соответствие требованиям и масштабируемость при росте данных. Для внедрения рекомендую поэтапный план: аудит текущих данных, пилот шифрования, обучение персонала.
