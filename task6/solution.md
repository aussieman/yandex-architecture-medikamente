# Задание 6: Классификация данных

## Проектирование движка классификации
Движок классифицирует и анонимизирует данные перед загрузкой в аналитическое хранилище. Учитывает неразмеченные данные, изменяющиеся структуры. Классификация: PHI (высокая), PII (высокая), Финансовые (средняя), Общие (низкая).

Движок: ETL-процесс с Apache Nifi для потоков данных, Microsoft Presidio для анонимизации, HashiCorp Vault для ключей. Интегрируется с Privacy by Design: анонимизация чувствительных данных.

## Проектное решение
Архитектура на диаграмме C2 (c2.drawio):
- **Источники данных**: Kafka (потоки), PostgreSQL (данные пациентов).
- **Data flow management (Apache Nifi)**: Управляет ETL, классификацией и маршрутизацией.
- **Anonimizer (Microsoft Presidio)**: Детектирует и анонимизирует PII.
- **Файловое хранилище (Minio)**: Хранит PHI с шифрованием SSE-S3.
- **Key Management Service (HashiCorp Vault)**: Управляет ключами шифрования.
- **Хранилище аналитических данных (ClickHouse)**: Хранит анонимизированные данные для BI.
- **BI Analytic**: Пользователь, запрашивающий данные.

Поток: Данные → Nifi → Anonimizer → ClickHouse; Файлы → Minio с шифрованием.

Дополнительные меры: Tagging, DLP, аудит.

## Метрики эффективности
- Точность классификации (precision/recall) - для улучшения моделей Presidio.
- False positives/negatives - мониторинг ошибок.
- Время обработки (latency) - оптимизация Nifi.
- Покрытие данных (coverage) - процент обработанных данных.

Помогает оптимизации: метрики для тюнинга, снижение рисков утечек, повышение скорости аналитики.

## Scalability
- Горизонтальное масштабирование: Kubernetes для Nifi, Presidio, ClickHouse.
- Облако: AWS для Minio, Kafka.
- При росте: Auto-scaling, partitioning в ClickHouse, sharding в Kafka.

Диаграмма C2: c2.drawio.
