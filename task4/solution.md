# Оценка узких мест при миграции

## Анализ ситуации
Текущая система "Медикаменте" - монолитная: 1С в файловом режиме, Excel для данных, файловый сервер на Windows Server. Цели миграции: переход на микросервисную архитектуру с шифрованием, RBAC, DLP, аналитикой. Ключевые компоненты: БД (1С, Excel), коммуникации (OLE/TCP), оборудование (физический сервер), бизнес-логика (ручные процессы).

Миграция затрагивает: перенос данных в зашифрованное хранилище, интеграцию микросервисов, обучение персонала.

## Диаграмма Исикавы
Диаграмма "рыбья кость" построена в draw.io (ishikawa.drawio). Голова: "Узкие места при миграции". Категории (кости):
- Инфраструктура
- Программное обеспечение
- Интеграция
- Персонал
- Процессы

Причины указаны в подветвях.

## Выявленные проблемы
- **Инфраструктура**: Недостаточная мощность сервера для микросервисов, риски сети (без VPN).
- **ПО**: Несовместимость 1С с новыми API, потеря данных при миграции Excel.
- **Интеграция**: Разрывы в API (например, с лабораторией), отсутствие шифрования.
- **Персонал**: Недостаток навыков в Kubernetes/PostgreSQL.
- **Процессы**: Ручные процессы замедлят автоматизацию, риски downtime.

## Рекомендации
Приоритеты: Высокий (критично), Средний (важно), Низкий (дополнительно).

1. **Высокий**: Обновить инфраструктуру (Kubernetes кластер). Мера: Аудит и апгрейд сервера.
2. **Высокий**: Обучить персонал. Мера: Курсы по микросервисам.
3. **Средний**: Тестировать интеграцию. Мера: Пилот миграции БД.
4. **Средний**: Внедрить мониторинг. Мера: ELK Stack для логов.
5. **Низкий**: Оптимизировать процессы. Мера: Автоматизация ручных задач.

## Заключение
Миграция рискованна из-за монолитности. Рекомендации минимизируют downtime и потери данных. Диаграмма в ishikawa.drawio.
